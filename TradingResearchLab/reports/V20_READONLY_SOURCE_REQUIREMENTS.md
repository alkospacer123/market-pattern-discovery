# TRL-00.5 — требования к независимому READONLY-источнику V20

**Статус: SOURCE IDENTIFIED FOR HEALTH ONLY / LIVE TRADE EXPORT UNVERIFIED.** Не обращаться к production SQLite/FINAM из TRL и не изменять LIVE.

## Что уже существует (проверено по исходникам, не runtime)

- `ControlCenter/deployment/v20_live_export.py` в Draft PR #568 формирует `cc.v20.readonly.v1` из локального оператора и журналов циклов. Комментарий исходника: без FINAM, DPAPI, SQLite, торговых команд.
- `ControlCenter/cc/v20_contract.py` проверяет поля: `schema_id, robot_id, account_alias, observed_at, heartbeat_at, engine_state, task_state, kill_switch, cycle, positions_local, stops_local, unresolved_local, last_error_code, events, payload_sha256`. Последних событий до 10.
- Поля `positions_local`/`stops_local` могут быть `null`. Экспорт **не содержит** историю закрытых сделок, денежный P&L, commissions или реализацию R.
- `V20_TradingSystem_M15/V20-08/v20-08-multi-position-readonly.py` в Draft PR #567 является диагностикой локального состояния через SQLite read-only. **Не запускать её из TRL**; она не заменяет обезличенный месячный экспорт.

## Что требуется для TRL Evolution

Отдельный, однократно сформированный и сохранённый **обезличенный файл** (например, CSV/JSON), созданный и проверенный средствами владельца LIVE-проекта. TRL только читает переданную копию.

**Метаданные:** `exported_at`, `period_start/end`, `strategy/robot`, `source_version`, `source_snapshot_id`, `sha256`, `is_complete`, критерий пропущенных данных, валюта и описание единиц.

**Данные сделок при доступности:** псевдоним робота, инструмент, направление, время сигнала/входа/выхода, цена входа/выхода, объём, исходный стоп, причина выхода, gross/net P&L RUB, комиссии и другие издержки, net R, MAE/MFE при наличии, статус сделки. **Без торговых токенов, номера счёта, order IDs, клиентских ID и иных секретов.**

**Отдельные агрегаты:** начальный и конечный капитал по роботу/портфелю (если разрешено экспортировать), фактический занятый ГО, дневная/месячная equity, риск и концентрация. Агрегаты должны быть сверены с исходной бухгалтерией, а не просто рассчитаны из сигналов.

**Проверки до принятия:** 3/3 робота, согласованный часовой пояс, уникальность записей, метки времени и валюта, открытые и закрытые сделки не смешивать, отсутствие данных не равно нулю, качество/полнота, воспроизводимость агрегатов, контрольная сумма файла. Только затем использовать в месячной карточке.

## Решение

- Разделять `CC-02 HEALTH SNAPSHOT` и `TRL FINANCIAL TRADE SNAPSHOT`. Первый **недостаточен** для полноценных метрик эффективности.
- Наличие авторизованного `TRL FINANCIAL TRADE SNAPSHOT` сейчас **не подтверждено**. Пункт 00.5 остаётся `HOLD_INPUT`, пока отдельный LIVE-проект не предоставит готовый проверенный READONLY-снимок. Никаких команд, фиксов или изменений LIVE из TRL.
