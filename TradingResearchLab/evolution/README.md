# TRL Evolution — ежемесячный анализ действующих систем

Здесь не хранится LIVE runtime и нет инструментов для подачи торговых заявок или изменения конфигураций. Только отдельные обезличенные READONLY-выгрузки и производные отчёты.

## Каждый месяц

1. Установить фактическую полноту экспортированных данных: период, три робота, присутствие сделок и пропусков. **НЕТ ДАННЫХ ≠ НОЛЬ СДЕЛОК.**
2. По Shallow, OBV, Inside отдельно: число входов/закрытий; gross/net P&L, net R и PF (только если данные достаточны); стопы/причины выходов; максимальная просадка; расходы; распределение результатов.
3. По портфелю: совокупный результат, общий риск, пересечения позиций, концентрация по инструментам. Избегать двойного учёта отдельных счетов.
4. Сопоставить с подходящим frozen V20 эталоном, учитывая отличия live исполнения, контрактов и периодов.
5. Записать: нормальное наблюдение / гипотеза для проверки / недостаточно данных. Изменения стратегии **не применять**.

## Каждый квартал

Выбрать одну обоснованную гипотезу улучшения из месячной статистики, провести независимое сравнение экспериментального варианта с frozen V20 и вынести решение. Негативные результаты сохранять.

**Входной контракт:** [V20_READONLY_SOURCE_REQUIREMENTS.md](../reports/V20_READONLY_SOURCE_REQUIREMENTS.md). До подтверждения источника численные LIVE показатели помечать `NOT_AVAILABLE`, а не `0`.
