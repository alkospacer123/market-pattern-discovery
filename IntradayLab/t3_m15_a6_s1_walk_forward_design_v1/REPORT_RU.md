## 3. Рекомендуемая хронология

Для frozen deterministic кандидата повторного обучения или подбора модели нет. Вместо rolling optimization нужна **последовательная проверка одной и той же стратегии**: expanding past-only состояние, непересекающиеся будущие квартальные отчётные блоки. Термин WF здесь означает перенос неизменного кандидата во времени; статистическая независимость рыночных блоков не предполагается.

Единственный рекомендуемый порядок:

1. Независимо проверить этот Draft PR и неизменность кандидата/границ. Его Merge сам по себе не разрешает чтение данных или исполнение WF.
2. Пользователь отдельно определяет точные даты и права доступа: нераскрытый 12-месячный WF, последующий непересекающийся 12-месячный TRUE OOS, необходимую предшествующую историю для прогрева и непрерывного состояния. Если это затрагивает текущую резервацию 2025+, решение явно меняет границу roadmap. Оно должно предшествовать любому чтению, включая timestamps/coverage 2025+.
3. До чтения новых данных зафиксировать календарный протокол, pins, версии, состояние на границе, критерии ниже и отдельный allowlist. Проверить provenance untouched-периодов и опубликованный CONTROL. При неподтверждённой независимости — DEVELOPMENT_EXPOSED / STOP; не искать удачное другое окно по P&L.
4. Исполнить четыре последовательных трёхмесячных блока W1→W2→W3→W4 одним кандидатом. Запечатать журнал каждого блока до открытия следующего. Накопленные прошлые бары доступны лишь для causal state/отчётности; параметры, стороны и состав неизменны. Завершить весь заранее назначенный WF, включая отрицательные блоки; остановка возможна при нарушении данных/протокола, с сохранением частичного результата, без WF PASS.
5. После полного 12-месячного WF — независимый аудит и решение пользователя по следующему этапу. TRUE OOS до этого закрыт. Затем, только по отдельному разрешению, одно финальное TRUE OOS assessment на заранее зарезервированном последующем окне. LIVE не следует автоматически.

Никакой календарный год 2025+ сейчас не отнесён к WF. Если двух таких подтверждённо untouched окон пока нет, ждать формирования новых данных; не уменьшать срок после плохих результатов.

## 4. Границы, OPEN и учёт результата

Календарные reporting intervals — полуоткрытые [start, end) в Europe/Moscow. Канонический trade outcome относится к **exit Close label**, включая exits по Open внутри бара: этот label сохраняется для совместимости и не утверждает точное intrabar время. Сигналы — по signal Close, исполнение — по фактическому adjacent Open. На отчётной границе event с label=end относится к следующему блоку и не читается ради предыдущего отчёта. Это причинная, детерминированная конвенция, а не перенос прибыли для улучшения блока.

Через W1/W2/W3/W4 продолжаются позиция, immutable initial R, active Stop, favorable extreme, S1 status, индикаторные рекурсии, H1 дневной блок и pending. Нельзя начинать каждый квартал FLAT, заново прогревать EMA с короткого окна, отменять граничный сигнал, ликвидировать OPEN по Close или делить сделку на несколько CLOSED. Один исходный CLOSED и полный Gross R попадают ровно в один exit-блок. Дополнительно публикуются entry-cohort, carried-in/carried-out IDs и входы из предыдущей exposed/state истории, чтобы не выдавать inherited результат за новый независимый сигнал.

Новая WF cohort содержит только сделки, у которых и signal Close, и actual entry принадлежат всему назначенному WF. Её CLOSED-метрики используют только выходы, известные до конца WF; оставшиеся OPEN раскрываются отдельно. Сделки W1, закрытые в W2–W4, входят в эту общую cohort один раз. Положительный результат inherited development/bridge позиции сам по себе не подтверждает переносимость новых WF входов.

На каждой границе — снимок из последнего разрешённого завершённого бара: ID, instrument/side, entry, initial Stop/R, active Stop, S1, extreme, last Close/time и unrealized gross R. Если до границы нет свежего бара — stale time раскрывается, недостающая цена не выдумывается. Pending проверяется на следующем строго соседнем Open только после открытия следующего разрешённого блока; отсутствие соседа = canonical skip. На закрытой границе результат остаётся UNRESOLVED, без чтения закрытой стороны.

Для интервала дополнительно показать gross marked-to-last-close изменение условной R-экспозиции:

`period_marked_R = sum(full_R_of_exits_labelled_in_period) + U_end − U_start`.

U — сумма unrealized initial R открытых позиций по последним доступным Close. Это бухгалтерская сверка OPEN и распределения R во времени, не доходность капитала, не настоящий equity MTM и не вход в CLOSED PF. Канонические positive months считаются по CLOSED exit-month R; положительные marked months показываются отдельной колонкой. При недоступном снимке marked показатель N/A, без заполнения нулём.

На границе WF→TRUE OOS state также сохраняется, но переносимые WF позиции/сигналы явно выделяются. Финальный TRUE OOS отдельно показывает полный calendar/marked результат с carry и outcomes только сигналов/входов из нового окна; carry не называется независимым OOS входом. OPEN на конце WF или OOS не закрывается и не оценивается по будущему исходу. Для решения о WF нельзя читать OOS даже ради закрытия одной сделки; повторный импорт её будущего CLOSED в уже запечатанный WF запрещён.

В CONTROL есть IMOEXF LONG с входом 30.12.2024 и последним известным состоянием 31.12.2024. Её будущий выход неизвестен и не подставляется. Если T0 отделён от этого prefix закрытым промежутком, нельзя перепрыгнуть его и считать старые Stops/индикаторы актуальными: требуется отдельное разрешение всего необходимого bridge. Для начала будущего continuous assessment нужно восстановить state причинно по разрешённой истории с прежней инициализацией, затем сохранить snapshot; новый FLAT-reset не разрешён этим дизайном.

## 5. Метрики и критерии без подгонки

Каждый квартал, накопленный WF и все 12 календарных месяцев: ALL_FOUR, каждый инструмент, LONG/SHORT и instrument×side. Публикуются CLOSED/OPEN/pending/skip/busy counts; gross PF, Gross R, expectancy, win rate, holding time; positive/zero/negative months, worst month, losing-month/trade runs; CLOSED-R DD и recovery с фиксированным exit_time/instrument/trade_id порядком; marked R/OPEN и coverage. Общий DD идёт непрерывно через кварталы, локальный DD отдельно. Нет усреднения квартальных PF: итоговый PF считается из объединённых сделок.

PF = сумма положительных CLOSED R / модуль суммы отрицательных CLOSED R; при отсутствии убытков — N/A с причиной, без фиктивного infinity PASS. Zero R не положителен. NO_COVERAGE, AVAILABLE_NO_CLOSED и WARMUP_NOT_READY разделяются. Denominator всех назначенных календарных месяцев сохраняется; дополнительно показывается available denominator, без его подмены в первичном результате.

Концентрация: вклад инструментов/сторон, best1/best3 months, top1/3/5/10 winners и их IDs; fixed diagnostics из #510 — leave-one-out, без best1/best3, без top1/3/5/10, −0,05R/−0,10R каждой CLOSED. Это арифметика неизменного журнала, без нового replay/отсечения. Ранги отдельно по полному WF и блоку, ties как #510. Доли signed net R при неположительной сумме N/A. Ноябрь2024 служит историческим предупреждением, не заранее выбранным исключением будущего месяца. Абстрактный R-stress не становится комиссией, C1 или FINAM cost model.

| Условие / свидетельство | Будущий статус и действие |
| --- | --- |
| Нет решения о границах/правах чтения | WF_DATA_BOUNDARY_NOT_AUTHORIZED; никакого исполнения |
| Leakage, изменённые правила, неуспешный CONTROL, несовпадение журналов/повтора, незаявленная граница | WF_INVALID; сохранить доказательства, STOP, исправление только через аудит |
| Недостаточное/неподтверждённое покрытие назначенного окна, нет CLOSED или неопределён PF в полном первичном WF либо в новой WF cohort | WF_INSUFFICIENT_EVIDENCE; не объявлять PASS, не расширять/сокращать окно по P&L |
| Полный WF или новая WF cohort: Gross R ≤ 0, gross PF ≤ 1 либо expectancy ≤ 0 | WF_GROSS_EDGE_NOT_CONFIRMED; inherited прибыль не компенсирует отсутствие нового edge; STOP для решения пользователя |
| Полный Gross edge положителен, но квартал/сторона/инструмент или fixed stress/exclusion теряет положительный знак | WF_MIXED; все отрицательные ячейки сохранены, без нового фильтра; независимый аудит и решение пользователя |
| Полный edge положителен, проверки достоверности пройдены, предыдущие mixed flags отсутствуют | WF_REVIEW_REQUIRED; аудит всей регулярности/DD/concentration/OPEN, затем отдельное решение о TRUE OOS; автоматического WF PASS нет |

Приоритет статусов: boundary block → INVALID → INSUFFICIENT → GROSS_EDGE_NOT_CONFIRMED → MIXED → REVIEW_REQUIRED. Уже увиденный отрицательный квартал не повод подбирать параметры или не открывать остальную часть заранее разрешённого WF.

Нулевые границы экономического знака не подгоняются; historical PF≥1,70, предпочтительный >2, 20/24 и DD12,628056R остаются **контекстом сравнения exposed CONTROL**, не автоматически перенесёнными требованиями к каждому кварталу или 12 месяцам. Новых fitted порогов DD, доли месяцев, концентрации, количества сделок и составного score нет. Месячная регулярность, ухудшение DD/recovery, переносимые OPEN и малые выборки могут ограничить переход даже при положительном PF. Если пользователь потребует численный risk/regularity gate, он должен быть отдельно зафиксирован до чтения новых данных; изменить порог после просмотра блока нельзя.

Успешная gross-проверка лишь поддерживает рассмотрение следующего исследовательского этапа. Реальные costs/slippage/spread/funding/tick-grid/fills/sizing/capital и условия cost-aware TRUE OOS требуют отдельной спецификации; ни roadmap C1 M5, ни R-stress не закрывают этот вопрос. Текущий дизайн ничего не объявляет послеиздержечным или LIVE_READY.
