## Предпосылки

- Отдельный FINAM-счёт **только M15 IntradayLab**, не идентичный действующему H1 по account fingerprint. Собственная область Intel runtime и доступ; **не использовать, не читать и не изменять DPAPI/token/H1 SQLite/Task**.
- Отдельный M15 **READONLY API token**. Вызов `POST /v1/sessions` служит только получению JWT-сессии; затем `POST /v1/sessions/details` должен подтвердить **`readonly == true` и строго один `account_ids == [expected_m15_account_id]`**. Любое несовпадение -> STOP (без GET к чужому счёту).
- До авторизованного локального provision нет права запускать физические REST-вызовы. Никаких секретов/номеров счёта/полных REST bodies или JWT в GitHub, отчётах и чате.
- Для проверки M15 баров пользоваться только `GET /v1/instruments/{symbol}/bars?timeframe=TIME_FRAME_M15&interval.start_time=...&interval.end_time=...` и `GET /v1/assets/{symbol}/schedule`; при необходимости READONLY `GET account/orders`. Запрещены реальные order/SLTP/cancel.
- Официальная REST документация: <https://api.finam.ru/docs/rest/>. Для TIME_FRAME_M15 документирована глубина **30 дней**. Поэтому свеча IMOEXF 09.09.2026 уже вне этого REST lookback на 16.10.2026 и **не должна требоваться** в этом шаге; конфликт разрешён сравнением pinned M5/M15 в [аудите №08](data_intake/STEP08_IMOEXF_M5_CONFLICT_RESOLUTION_20261016.md).
