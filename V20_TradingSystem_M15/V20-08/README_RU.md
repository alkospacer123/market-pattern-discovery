## 08.1: проверка трёх независимых торговых токенов FINAM — READY / INTEL NOT RUN

`Verify-TradingTokens-Readonly.py` использует **неизменённые H1 FinamAPI, margin, production_broker_state и funding_margin_diagnostic**, сверяя их с точными Git blob SHA, а также предыдущие 06.1 / 06.4 funded / 07.4 receipts. Запускать отдельным локальным `C:\V20Lab\.venv-raw\scripts\python.exe` с файлом в `C:\V20Lab\pretrade-08\`.

Первый запуск `--self-test` проверяет без сети/токенов запрет ордерных URL и чтения чужого счета; проверяет отказ `readonly=true` и чужому account_id. Второй `--connect` интерактивно запрашивает три пары **account_id + отдельный WRITE-capable торговый токен**. Токен вводится видимо в PowerShell (ни всплывающего окна, ни PowerShell-history с секретом). Токены и номера счетов не записываются в GitHub, stdout, JSON или файл. Общий READONLY-токен 06.1 не подходит для этого шага и остаётся диагностическим.

Единственные разрешённые сетевые вызовы: **POST авторизации сессии**, **GET целевого счета** и **GET текущих заявок этого счета**. `POST orders`, `POST SLTP`, `DELETE`, заявки и другие FINAM URL запрещены **до** H1 HTTP транспорта. Session details должны показывать `readonly=false`, целевой счёт должен входить в `account_ids`; три токена должны различаться. H1 financial parser и broker state проверяют деньги, equity, свободное ГО, позиции и активные заявки. На успешной проверке только трёх чистых счетов будет `V20_08_1_TRADING_TOKEN_GET_ONLY=PASS_3_OF_3_GET_ONLY`. Это **не означает PASS 08.1** и **не означает разрешения реальной заявки**.

Локальный результат: `C:\V20Lab\pretrade-08\TRADING_TOKEN_ACCOUNT_READONLY_REPORT.json` — однократный, без перезаписи, без plaintext account_ids или торговых токенов. На случай ошибки в stdout/stderr появляется только безопасный `V20_08_1_BLOCKED=...`. Не копировать в чат строки, на которых вводились значения account_id или токена; сообщать только итоговые строки статуса.
