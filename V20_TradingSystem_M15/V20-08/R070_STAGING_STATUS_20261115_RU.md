## TP6 + Protect3: OFFLINE contract 15.11.2026
- `v20_runtime/tp6_protect3.py`: чистые расчёты уровней по **фактическим** FINAM
  fill quantity и VWAP, первоначальному SL на биржевом тике и точному Decimal.
  TP = ±6R, подтверждённый триггер +3R, новый SL ±1R.
- `sltp_tp6_fields()` добавляет TP на **100%** к единому SLTP-проекту
  с уже обязательным исходным стопом на 100%. Только offline-draft;
  никакой торговый POST/DELETE из этого модуля невозможен.
- `review_completed_m15()`: нужна подтверждённая **закрытая** M15; ранняя
  свеча запрещена; стоп/TP внутри той же M15 требует сверки FINAM (stop-first
  модельная последовательность), перенос запрещён до следующей M15, новый
  SL никогда не ухудшает предшествующую защиту.
- `place_or_replace_protect3_live()` всегда возвращает
  `FINAM_SLTP_NO_GAP_REPLACEMENT_NOT_PROVEN`. По FINAM REST API на
  15.11.2026 подтверждены POST создания / GET / DELETE SLTP, но документированной
  атомарной поправки действующей SLTP не обнаружено. НЕ посылать второй
  100%-SLTP поверх первого без подтверждения брокера: возможен двойной выход.
  Официальные источники: https://api.finam.ru/docs/rest/ и
  https://api.finam.ru/changelog/2-13-0/ .
- Исходный эталон R060 `engines/cap_all_at_equity/combined_research.py`:
  стоп/TP intrabar stop-first; +3R по High/Low одной завершённой M15 и
  повышение стопа только на последующей M15; лимит третьей наблюдаемой
  сессии приоритетнее остальных проверок выхода.
- Проверка оригинального `r060_all_cash_trades.csv`, OCT GO,
  V20_603045 + EXT2: **173 из 173** `TP_INTRABAR` соответствуют точно
  уровню ±6R после приведения исходных float-значений к биржевому тиковому
  шагу. Это проверка эталонной **арифметики**, а не доказательство
  LIVE-исполнения или стоп-модификации. Три GLD float-значения имели
  шум представления 1e-12; настоящий SL FINAM должен быть на точной сетке.
- Проверка в существующем Windows CI:
  `tests/test_tp6_protect3.py` и `tests/test_ext2_r060.py`.
  Ни одна функция нового модуля не вызывается `finam_live.py`.

## 16.11.2026 — EXT2 M15-source bridge (OFFLINE, no LIVE)

Официальный FINAM REST Bars `GET /v1/instruments/{symbol}/bars`:
`TIME_FRAME_M15` **глубина 30 дней**, `TIME_FRAME_D` **365 дней**.
`TIME_FRAME_D` НЕ подменяет R060 M15→D из сессии 10:00–17:45.
Источник: https://api.finam.ru/docs/rest/, MarketDataService/Bars.

Пределы проверенного исследовательского архива R060:
- USDRUBF и CNYRUBF заканчиваются **30.08.2026**;
- GLDRUBF и IMOEXF заканчиваются **15.09.2026**.

Следовательно, на 16.11.2026 текущие последние 30 дней из FINAM не
перекрывают этот R060 ZIP. При попытке прямого объединения обязан
получиться `EXT2_SEED_FINAM_OVERLAP_MISSING`, а НЕ вычисление
D ATR по вымышленным свечам.

Добавлен `v20_runtime/ext2_history_bridge.py`:
- проверка **точного SHA256** каждого оригинального CSV R060;
- проверка символа, M15 сетки/порядка, OHLCV и завершённого сигнального бара;
- объединение только при совпадении общих M15 (все OHLCV), без подмены
  бара при несовпадении;
- проверка завершённой предыдущей D-сессии и наличия Wilder D ATR14;
- fail-closed при отсутствии совпадающего покрытия, missing/partial input;
- **ни одного API-запроса, торгового метода либо SQLite-модификации**.
Проверки `tests/test_ext2_history_bridge.py` добавлены в существующий CI.
