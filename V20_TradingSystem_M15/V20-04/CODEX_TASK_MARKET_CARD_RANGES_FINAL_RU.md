# Задача Codex — завершение диапазонов универсальной карточки, V20-04.2

## Контекст и цель

Продолжай проект **только** `V20_TradingSystem_M15`, актуальную ветку Draft PR #567 `codex/v20-04-all-three-offline-foundation-20261021`. Перед началом проверь фактические GitHub main/head PR и `AGENTS.md`. База предыдущего завершённого анализа: commit `684f0ca5585d496c89fd1eb56e36c66d75a58717`, отчёт `V20-04/MARKET_CARD_RESEARCH_V2_RU.md`, машинный `MARKET_CARD_RESEARCH_V2.json`, код `v20_runtime/market_outcome_research.py`. Уже есть пять показателей, правильные CLV×Volume и строгий Inside; **не переделывать**.

**Цель — один конечный и простой эксперимент:** проверить гипотезу владельца, что существует понятный **диапазон «от–до»** рыночной характеристики, внутри которого исходные V20-сигналы получают более качественное последующее движение, а снаружи хуже. Корреляция ~0 сама по себе не опровергает интервальную/нелинейную зависимость. Не запускать масштабный поиск, не оптимизировать PF, не добавлять этапы.

## Строго ограниченная методика

1. **Используй уже подготовленные causal observations** из V20-04.2: пять групп, признаки строго на полностью завершённых M15 *до* raw-сигнала, `horizon_R` исходного третьесессионного срока *только как outcome*. Источник: 4 986 `RAW_SIGNAL` из `V20-03/comparison/QUOTE_PATH_DIAGNOSTICS.csv`; сопоставленных признаков без заблокированного 2025 сейчас 1 604. Не применять `ACCEPTED`/квоты или итоговый PnL как фильтр популяции. Не допускать future leakage.
2. **Раз и заранее зафиксируй границы по распределению, не по результату:** для 2023–2024 вычисли p25 и p75 каждого заранее выбранного показателя. Разбей по этим двум границам на `НИЖЕ`, `ВНУТРИ`, `ВЫШЕ`. **Нельзя подбирать другие процентили, расширять список показателей или менять диапазоны для улучшения PF/horizon_R.** Если percentile-база мала/нестабильна, признак `НЕ ПРОВЕРЕНО`. Границы одинаковые, без переопределения при применении к 2026.
3. Для каждой из 3 корзин **покажи обязательно N raw-сигналов, средний и медианный `horizon_R`, долю `horizon_R > 0` и долю касания исходного стопа** из уже опубликованной path диагностики. Раздельно **2023–2024 (описательный эталон) и 2026 YTD (временная проверка)**, плюс разбивка N4 по инструментам там, где выборка позволяет. 2026 уже изучался V20, поэтому *не* обозначать его independent OOS.
4. **Один общий диагностический ATR/Close** и **по 1 главному strategy-specific признаку**: Shallow — продолжение пробоев; OBV — согласованность исходного CLV×Volume с движением; Inside — сжатие / строгий Inside (выбрать конкретную уже существующую метрику без перебора). Направленность ER и оставшиеся показатели сохраняются в пяти группах карточки и её подробностях, но не создают дополнительных барьеров. Не создавать пять фильтров AND.
5. **Вывод сделать по обоим периодам, а не только по прибыльному эталону**: если значения внутри диапазона НЕ устойчиво лучше внешних на 2026 либо мало наблюдений, честно отметить `НЕ ПОДТВЕРЖДЕНО`. Изменение состава N4 и неоднородность между инструментами отметить без корректировок под PF. Старый 2018–2022 без исходных M15 для всех пяти признаков не реконструировать догадками; имеющиеся значения +0,406R / +0,953R Shallow, +0,226R / +0,695R OBV, +0,205R / +0,733R Inside сохранить как **raw horizon outcomes**, не PnL.
6. **Минимально довести карточку**, без нового UI/сервиса: по умолчанию инструмент, время, три стратегии и 1–2 понятных причины; можно добавить одну компактную строку `значение сейчас / типичный диапазон p25–p75 (2023–24) / ниже-внутри-выше` по релевантной метрике. **Типичный диапазон НЕ объявлять автоматически прибыльным**. Подробные пять групп остаются по `--details`/JSON. Если границы не подтверждают улучшения исходов, честно показать это, а не окрашивать как `НЕДОПУСТИМО`.
7. **Оценки** `ДОПУСТИМО / НЕЙТРАЛЬНО / НЕДОПУСТИМО` — только при действительно проверенном правиле. **Не обходить проверку evidence и independent holdout в `market_verdict.py`**, не подсовывать фиктивный PASS/hash и не утверждать, что независимое тестирование состоялось. Если доказательств не хватило, сохранять `НЕ ОЦЕНЕНО` (либо `НЕДОСТАТОЧНО ДАННЫХ`); сама информация `ВНУТРИ ТИПИЧНОГО ДИАПАЗОНА` допустима как отдельный, явно описательный факт. Не пытаться любой ценой выдать три готовых «зелёных» статуса.

## Проверить ровно необходимое

- Ни один признак/порог не использует данные дня сигнала или после него; `horizon_R` никогда не входит в текущие признаки.
- p25/p75 вычислены только из 2023–24, без `2025` и `2026`, при проверке 2026 неизменны; **`AGENTS.md` строго запрещает даже чтение locked 2025 в новой feature-discovery обработке.**
- Если нет достаточного числа сигналов или календарь не подтверждён, вывод отражает неопределённость.
- Актуальный `main`, H1, IntradayLab M15, frozen research sources, `robots.json`, ордера, стопы, риск, три независимых счёта и FINAM не трогать. Offline-only. Никакого TradingSystemLab/M15 rearm, Shadow, LIVE и новых этапов.
- Минимальные синтетические тесты интервалов, граничных значений, причинного cutoff, `p25/p75`, 2025 lock, неполных данных, отсутствия влияния на торговлю. Запустить текущие узкие тесты; 61 старый тест не засчитывать повторно как результат нового кода без запуска.
