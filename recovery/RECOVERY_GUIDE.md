# Recovery Guide — восстановление V20, Control Center, TRL и памяти

## Защита от непреднамеренной торговли
Весь первый запуск — **OFF / READONLY / ISOLATED**. Нет автоматического rearm, live RUN, broker order/cancel, токенов или возобновления Windows Scheduled Tasks. Инструкция — план восстановления, НЕ разрешение на торговлю. Каждое действие у брокера требует свежего подтверждения владельца и сверки его фактических счетов/позиций/стопов.

## Инвентарь
На SSD должны быть независимые датированные копии V20+CC: ZIP, его `.zip.sha256`, `.report.json`, контрольные суммы, документация/Agent. Оригинальный 02.11: `RECOVERY-BASE-V20-CC-20261102-224947.zip` и сопроводительные файлы; после фиксов нужен новый снимок с новым SHA, PASS. Проверить на SSD SHA256 не по имени, а вычислением и сверкой с отчётом. Хранить также Git mirror и экспорт/копии разговоров, когда доступны.

## Последовательность на новом ПК
1. Физически изолировать новую среду от автоматической торговли (сеть/FINAM live/Tasks без запуска), создать учётную запись оператора и место для развёртывания.
2. Провести проверку SHA256 ZIP + отчёта, тест ZIP CRC, внутренних file hashes и SQLite online backup. Отсутствующие/изменённые файлы/снимки => **FAIL**, остановиться.
3. Распаковать V20 и Control Center в документированные каталоги на **тестовом** томе/Windows с сохранением NTFS-атрибутов/ACL по необходимости. Учитывать, что ZIP может не сохранять полный набор security descriptors и альтернативных потоков NTFS — восстанавливать и проверять разрешения отдельно.
4. Не восстанавливать три `v20-instance.lock`: это временные locks, они создаются процессами при работе; отсутствие ожидаемо.
5. Из согласованных SQLite-снимков восстановить требуемые БД только при остановленном worker и с подтверждённым порядком восстановления. Старое broker state не является источником истины: **до нового старта** отдельно сверить брокера.
6. Воссоздать Python/венв зависимости из проверенных локальных pinned артефактов; сохранить целостность источника/хэшей. Проверить версии Python/Streamlit, digest кода, timestamp, runtime config, scheduled tasks, SID/DPAPI и CC-02 pins. До изоляционной приёмки Windows Tasks не активировать.
7. Выполнить unit/regression, READONLY checks, локальные проверки idempotency/recovery/stop/GO/tick-grid и панель loopback. Отсутствующий FINAM READONLY/секрет => UNKNOWN, не обходить guard.
8. Оператор вручную восстанавливает необходимые FINAM-токены из своего отдельного защищённого источника, заново привязывает DPAPI к Windows CurrentUser; секреты в GitHub/ChatGPT не загружать.
9. Перед разрешением торговли: точный broker flat/open-positions/open-orders/SLTP, риск, ГО, kill switch, отсутствие дубликатов, pending и durable markers; документированная физическая приёмка для каждого робота; отдельное решение владельца о LIVE.
10. Запускать только по утверждённому LIVE runbook с проверками 1→2→3; H1 и M15 не включать. После запуска сохранять новый recovery checkpoint и журнал.

## Восстановление исследовательской памяти
Новый ИИ начинает с [Agent.md](Agent.md), [PROJECT_MASTER](PROJECT_MASTER.md), [DECISIONS](DECISIONS.md), [TIMELINE](TIMELINE.md), затем GitHub TRL / V20 / CC первоисточников. Для исследования нет необходимости запускать FINAM или Live workers. Если ChatGPT export отсутствует, использовать восстановленную память с явными gaps.

## Пробная приёмка
Итоговый статус `COLD_RESTORE_PASS` только если распаковка, hashes, критичные SQLite, программа в READONLY, интерфейс и isolated tests фактически прошли на другой машине. Архив `CAPTURED_NOT_RESTORE_TESTED` не считать GOLD. Не выполнять destructive cleanup старого SSD до успешного восстановления.
