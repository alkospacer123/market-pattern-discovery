# Правила актуализации RECOVERY MEMORY

## Когда обновлять
- После каждого значимого LIVE фикса/приёмки: `CURRENT_STATE_YYYY-MM-DD.md` и `TIMELINE.md`; фиксировать PR/SHA, installed SHA, PASS/FAIL и broker/SLTP свидетельства.
- После принятого архитектурного или финансового решения: append-only `DECISIONS.md` со статусом (DECIDED / RESEARCH / REJECTED).
- После месячного/квартального TRL цикла: ссылка на Journal и отчёт; отсутствие finance data помечать HOLD_DATA.
- После каждой проверенной копии: архивное имя, SHA256, файлы, SQLite snapshots, verification, SSD copy, cold-restore result.
- После получения экспорта ChatGPT: **сверить** события, даты, оригинальные формулировки, добавить пропущенные решения; не загружать сырой приватный экспорт в публичный GitHub.

## Разделение хранения
1. Публичный GitHub — только очищенная документация, безопасные исходники/тесты и кросс-ссылки. Никаких токенов, PII, order IDs, raw financial logs, производственных SQLite или приватного текста.
2. Внешний шифрованный SSD — полные файлы V20+CC, отчёты и dumps, плюс Git mirror и отдельный архив ChatGPT; обязательно проверять SHA после копирования.
3. Облако — только зашифрованная автономная копия с отдельным восстановимым ключом; не привязывать единственный ключ к утерянному аккаунту.
4. 125 ГБ H1/M15 не входили в текущий состав; не «оптимизировать» оригинальные данные на работающем Intel.

## Критерии полноты
- `MEMORY_RECONSTRUCTED` — документы созданы.
- `MEMORY_RECONCILED` — сверены с полным первоисточником/архивом.
- `FILES_VERIFIED` — ZIP и SHA проверены.
- `COLD_RESTORE_PASS` — изолированное восстановление на другой Windows действительно испытано.
- `RECOVERY_GOLD` — актуальная стабильная установленная версия + полная память + independent copy + проверенный cold restore.

Ни одна отдельная отметка сама по себе не означает остальные.
