# Правила актуализации RECOVERY MEMORY

> **Контроль документации после R7 (22.11.2026):** [матрица приоритета и проверенных ссылок](DOCUMENTATION_AUTHORITY_2026-11-22.md). В датированных отчётах не заменять старые результаты/проверенные SHA современными статусами. Текущий операционный статус менять только по свежей физической проверке; GitHub SHA — датированный pin. Для Kimi каждый новый Merge означает новую сверку base HEAD и source blobs.


## Когда обновлять
- После существенной задачи, решения или блокера: существующий профильный STATUS и компактная запись JOURNAL (TRL — датированные записи в journal/), по [AGENTS](../AGENTS.md). Для сквозной координации — [Recovery STATUS](STATUS.md) и [JOURNAL](JOURNAL.md). Не создавать отдельные CURRENT_STATE/TIMELINE/DECISIONS ради повтора информации; прежние файлы — история. Сохранять PR/SHA, фактические installed/LIVE evidence и UNKNOWN только в доказанных границах.
- После месячного/квартального TRL цикла: ссылка на Journal и отчёт; отсутствие finance data помечать HOLD_DATA.
- После каждой проверенной копии: архивное имя, SHA256, файлы, SQLite snapshots, verification, SSD copy, cold-restore result.
- После получения экспорта ChatGPT: **сверить** события, даты, оригинальные формулировки, добавить пропущенные решения; не загружать сырой приватный экспорт в публичный GitHub.

## Разделение хранения
1. Публичный GitHub — только очищенная документация, безопасные исходники/тесты и кросс-ссылки. Никаких токенов, PII, order IDs, raw financial logs, производственных SQLite или приватного текста.
2. Внешний шифрованный SSD — автономные копии V20, CC, TRL, необходимых H1/M15 зависимостей, данных, исследований и знаний обоих ИИ, включая отчёты, согласованные snapshots и Git mirror; секреты отдельно; обязательно проверять SHA после копирования.
3. Облако — только зашифрованная автономная копия с отдельным восстановимым ключом; не привязывать единственный ключ к утерянному аккаунту.
4. 125 ГБ H1/M15 не входили в текущий состав; не «оптимизировать» оригинальные данные на работающем Intel.

## Критерии полноты
- `MEMORY_RECONSTRUCTED` — документы созданы.
- `MEMORY_RECONCILED` — сверены с полным первоисточником/архивом.
- `FILES_VERIFIED` — ZIP и SHA проверены.
- `COLD_RESTORE_PASS` — фактически доказано автономное восстановление V20, CC, TRL и знаний на независимой среде без Intel, основного SSD, GitHub и обоих ИИ, по утверждённым критериям этапа III; частичная приёмка не равна полному PASS.
- `RECOVERY_GOLD` — актуальная стабильная установленная версия + полная память + independent copy + проверенный cold restore.

Ни одна отдельная отметка сама по себе не означает остальные.
