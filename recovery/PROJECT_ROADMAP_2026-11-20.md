# Trading Systems — актуальный Roadmap 20.11.2026

**Принятый порядок:** R0 → R4 → защитный снимок → R7 → R1 → R2 → R3 → R5 → R6 → R8. Допускается параллельная read-only подготовка.

| Этап | Содержание | PASS требует |
|---|---|---|
| R0 Inventory | Сверить MAIN/INSTALLED/LIVE/RESEARCH/ARCHIVE/RECON, 11 Draft и исходные архивы | Реестр уникальных материалов, SHA, первоисточников, пробелов и предложений владельцу |
| R4 Finalization | Зафиксировать принятые исходники и незакрытые дефекты после цепочки merge | Сверка V20/CC с Intel и свежими свидетельствами; регрессии; новые фиксы отдельными PR |
| Защитный снимок | Сохранить полную Git-историю и критичные материалы до реорганизации | Независимая копия, SHA, откат. Это НЕ R5 Final Backup и НЕ R6 Restore Test |
| R7 GitHub Reorganization | Три чистых репозитория V20/CC/TRL в `alkospacer123`, исторический архив, отдельный `market-pattern-data` | Сохранение provenance, refs/PR/Issues/CI и истории; удаление `market-pattern-autonomous-engine` отдельно разрешено; LIVE не переключён |
| R1 Knowledge Transfer | R1.1 общий фундамент, R1.2 V20, R1.3 CC, R1.4 TRL, R1.5 экзамен, R1.6 GPT↔Kimi передача задачи | Kimi находит доказательства и SHA, воспроизводит доступные тесты и продолжает безопасную работу |
| R2 Kimi Integration | Три проекта Kimi, изолированный Kimi Code, read/write, ветки, PR, CI, отдельные доступы | Права и взаимозаменяемость реально проверены, нет LIVE доступа по умолчанию |
| R3 Joint Development | Совместная безопасная разработка, тесты и независимое review | Документированная передача задачи и операторское разрешение на merge |
| R5 Final Backup | Полный итоговый комплект кода, знаний, Git, SQLite, TRL данных, журналов и чатов | Шифрованная независимая копия вне Intel/основного SSD, манифест, SHA и способность к чтению |
| R6 Restore Test | Изолированное восстановление трёх систем и знаний, без Intel/SSD/GitHub | Проверенные файлы, тесты и продолжение работы без торговли; FINAM/DPAPI отдельно |
| R8 Acceptance | Принять инфраструктуру, права ИИ и доказательства | Датированные PASS/FAIL, остаточные риски, откат, решение владельца |

Для каждого этапа: цель, риски, доказательства, PASS/FAIL, откат. Не объявлять PASS по одному SHA256 или CI.
