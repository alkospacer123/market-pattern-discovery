# Agent.md — восстановление контекста для нового ChatGPT / другого ИИ

**Дата среза:** 2026-11-09. **Задача агента:** продолжить долгосрочные проекты владельца, а не начинать их заново.

## Обязательное чтение
Последовательно прочитать `recovery/README.md`, `PROJECT_MASTER.md`, `CURRENT_STATE_2026-11-09.md`, `DECISIONS.md`, `TIMELINE.md`, три паспорта и `EVIDENCE_AND_GAPS.md`. Затем открыть документы / код соответствующих модулей и сверить с последним зафиксированным commit/SHA и фактическим состоянием Intel/FINAM. Обновления после даты среза искать отдельно. Не выдавать срез за live-статус.

## Проекты и разрешения
- **V20:** три независимых LIVE-робота Shallow, OBV, Inside; N4 (USDRUBF, CNYRUBF, GLDRUBF, IMOEXF); работа с реальными ордерами — **только** в отдельном операторском чате и после разрешения владельца. Стратегии заморожены. Не менять риски, условия входа, выходы, H1/M15, FINAM, Windows Tasks, SQLite без отдельной задачи и проверки.
- **Control Center:** интерфейс и безопасные READONLY/CC-07 функции. Не путать `Running` задачи, `ARMED`, успешный цикл, защиту SLTP и подтверждённое состояние брокера. Не запускать торговую систему ради проверки панели.
- **TRL:** Research, Evolution, Journal. Работать исключительно с данными READONLY, воспроизводимыми тестами, cost-aware анализом и зафиксированными решениями. TRL не проводит LIVE-операций, не подключается напрямую к FINAM и не редактирует production SQLite.

## Научная дисциплина
Результаты по схеме baseline → optimization → robustness → walk-forward → TRUE OOS; запрет look-ahead и data leakage; расходы C1 для исследовательских сравнений, реальные брокерские расходы отдельно; никакого ML без нового разрешения. Не переносить статусы OOS между историческими исследованиями: действуют исходные документы каждого протокола. Тест на множестве раз исследованных 2018–2026 нельзя автоматически объявить независимым OOS.

## Операционная дисциплина
1. Любое действие предварять проверкой источника и текущего рабочего состояния; статус при отсутствии свидетельства — UNKNOWN/NOT_VERIFIED, не PASS.
2. На новом Windows сначала восстановить и сверить файлы, SQLite-снимки, зависимости, scheduled tasks и учетные права в **невооружённом** режиме. Никакой автоматической установки ARMED или подачи заявок.
3. Первичное восстановление FINAM/DPAPI выполняет оператор с отдельно сохранёнными секретами и повторным связыванием SID. Не просить раскрывать секреты в чат.
4. Для PowerShell — по возможности однострочные команды в нижнем регистре, без всплывающих окон для паролей; использовать установленный / venv Python, не `py.exe`.
5. После обнаружения сбоя — локальный READONLY, журнал, факты у брокера, гипотеза, минимальный фикс, регрессии, CI, контролируемая установка и независимая физическая приемка.
6. PR, CI SUCCESS и GitHub SHA сами по себе не подтверждают установленную версию на Intel.
7. Не создавать дополнительные стадии сверх утверждённого V20 roadmap (V20-01…V20-08). Не смешивать исследования улучшений и внедрение LIVE.

## Как продолжать обсуждение
Уточнять только недостающие данные, которых нет в документации. Сначала: какой из трёх проектов и какой контур (research vs LIVE). Сообщать, какие сведения извлечены из исходников, журнала, слов владельца или реконструкции; задавать конкретную проверку, если факт меняется со временем. Никогда не утверждать, что ИИ «помнит всё» после переноса архива.
